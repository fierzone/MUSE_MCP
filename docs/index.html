Use Meta Muse from any MCP or OpenAI client

Muse has no public API — its chat is an encrypted Noise WebSocket. Muse-Chat-MCP drives your real, logged-in Chrome instead, then exposes Muse as MCP tools and as an OpenAI-compatible HTTP endpoint. Your account, your quota.

Get started → View on GitHub

Two front doors

Pick the interface that fits your stack — both are backed by the same browser driver.

🧩

MCP server (stdio)

Seven tools — muse_chat, muse_status, muse_login, muse_new_chat, muse_read_last, muse_dump_dom, muse_close. Works in Claude Desktop, opencode, Cursor, any MCP host.

🔌

OpenAI-compatible shim

GET /v1/models and POST /v1/chat/completions with real SSE streaming, correct finish_reason, and prompt-injected tool calling. Point any OpenAI SDK at it.

Features

No API key

Uses your existing Muse login in a dedicated Chrome profile — or attaches to a Chrome you already run.

Never kills Chrome

When attached over CDP, close() only disconnects. Your browser keeps running.

Auto CDP fallback

If the profile is locked by a running Chrome, it attaches over the debugger instead of failing.

Correct streaming

Only stable, monotonic DOM text is emitted, so a mid-answer rewrite never duplicates in the SSE stream.

Tool calling

Expose OpenAI tools; Muse returns tool_calls (decision-only, so it won't try to execute them).

No browser download

Drives your installed Chrome via playwright-core — nothing extra to download.

Quickstart

Prerequisites: Node.js ≥ 18, Google Chrome, and a Meta account with access to Muse.

git clone https://github.com/fierzone/MUSE_MCP.git
cd Muse-Chat-MCP
npm install
npm run selftest   # opens Chrome to muse.ai — sign in once; the session is saved

Then wire it into a client:

# MCP (stdio)
node /absolute/path/to/Muse-Chat-MCP/muse-server.mjs

# OpenAI-compatible shim only (HTTP on :8787)
node /absolute/path/to/Muse-Chat-MCP/muse-server.mjs --serve-only

# one-shot CLI
node muse-cli.mjs --no-stream -s "Output ONLY raw code." "Write a CSV parser"

Client config

opencode — as both an MCP server and an OpenAI-compatible provider:

"mcp": {
  "muse": {
    "type": "local",
    "command": ["node", "/abs/Muse-Chat-MCP/muse-server.mjs"],
    "enabled": true,
    "timeout": 300000
  }
},
"provider": {
  "muse-local": {
    "npm": "@ai-sdk/openai-compatible",
    "name": "Muse (local shim)",
    "options": { "baseURL": "http://127.0.0.1:8787/v1", "apiKey": "muse-local" },
    "models": { "muse-spark-1.3": { "name": "Muse Spark 1.3" } }
  }
}

Claude Desktop — claude_desktop_config.json:

{
  "mcpServers": {
    "muse": { "command": "node", "args": ["/abs/Muse-Chat-MCP/muse-server.mjs"] }
  }
}

OpenAI-compatible shim

from openai import OpenAI
client = OpenAI(base_url="http://127.0.0.1:8787/v1", api_key="muse-local")
r = client.chat.completions.create(
    model="muse-spark-1.3",
    messages=[{"role": "user", "content": "Write a haiku about browsers."}],
    stream=True,
)
for chunk in r:
    print(chunk.choices[0].delta.content or "", end="")

stream + non-stream

SSE chunks with delta.content and a single finish_reason, then [DONE].

tools

Pass tools; get OpenAI tool_calls back (prompt-injected, best-effort).

headers

x-muse-thread: new and x-muse-timeout-ms.

How it works

MCP client (Claude Desktop / opencode) OpenAI client (SDK / provider) │ stdio (JSON-RPC) │ HTTP /v1/* ▼ ▼ muse-server.mjs ─────────► muse-openai-shim.mjs ┘ │ (7 MCP tools) (SSE + JSON) └──────────────┬──────────────────────────────┘ ▼ muse-driver.mjs (playwright-core) ▼ Chrome (dedicated profile ./.muse-profile) ──► https://muse.ai

Muse chat is not REST — it's an RPC gateway over an encrypted WebSocket (wss://hatch.metaaivm.com/v1/noise, Noise: X25519 + HKDF + AES‑GCM + Ed25519). The app does all crypto itself; we read the rendered reply. A headless Noise client is on the roadmap.

Reproduce it yourself

Requirements: Chrome + any coding agent (Claude Code, Codex, opencode, Cursor…). Capture the app's real traffic, then let the agent write the bridge.

1 · Capture

Chrome → F12 → Network → tick Preserve log. Filter Fetch/XHR and WS. Send a few prompts, then right-click → Save all as HAR with content → with sensitive data.

2 · Hand it to an agent

Give the .har to your coding agent and ask it to identify the transport, endpoints, auth, and the encrypted WebSocket — then design an MCP + OpenAI bridge.

Analyze captures/muse.har from a web chat app and report:
1) The chat transport: REST/SSE vs WebSocket. List the endpoints (auth, session,
   wake, chat) and how auth works (cookies? tokens?).
2) The WebSocket: URL, subprotocol, whether frames are encrypted/binary (e.g. a
   Noise handshake: X25519 + HKDF + AES-GCM + Ed25519), and the RPC method names.
3) The most robust way to build a local bridge exposing this chat as (a) an MCP
   tool and (b) an OpenAI-compatible /v1 endpoint — given there is no official API.
A HAR "with sensitive data" contains your session cookies and tokens — never commit or share it. (This repo's .gitignore blocks *.har.)
